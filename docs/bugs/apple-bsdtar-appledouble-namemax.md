# macOS bsdtar AppleDouble metadata restore overflows NAME_MAX at the 255-byte name boundary

**Status:** evidence complete, ready to file · **Target:** Apple Feedback
Assistant (Apple's bsdtar copyfile integration) · **Found by:** memex CI

## Summary

Without `COPYFILE_DISABLE=1`, macOS `tar` extraction restores AppleDouble
metadata by writing a `._`-prefixed sidecar next to each file. For a file
whose name is at the filesystem's 255-unit limit, the sidecar name becomes
`._` + 255 = 257 units, exceeding NAME_MAX, and extraction **fails** with
"Failed to restore metadata: File name too long" — even though the payload
file itself is perfectly legal.

## Reproduction (copy-paste)

```sh
cd "$(mktemp -d)"
python3 -c "open('a'*255, 'w').write('x')"     # legal 255-char name
tar cf out.tar --exclude out.tar .             # default format, metadata ON
mkdir restored
tar xf out.tar -C restored ; echo "exit=$?"    # -> error
```

Observed (macOS 26.5, arm64, APFS, bsdtar 3.5.3 / libarchive 3.7.4):

```
tar: ./<255 a's>: Failed to restore metadata: File name too long
tar: Error exit delayed from previous errors.
exit=1
```

With `COPYFILE_DISABLE=1` the same archive extracts cleanly — isolating the
failure to the AppleDouble metadata path, not the payload path.

## Why it matters

- Archives containing max-length names (generated by fuzzers, packers, or
  other platforms) fail to extract on macOS by default — with a confusing
  error that names the *payload* file, not the `._` sidecar that actually
  overflowed.
- The failure is silent about its cause: nothing tells the user the 2-byte
  `._` prefix is what crossed the limit.
- Any tool that shells out to system `tar` on macOS (package managers, backup
  scripts, CI restore steps) inherits the failure.

## Suggested behaviors (any one)

1. Skip AppleDouble metadata restore (with a notice) when the sidecar name
   would exceed NAME_MAX, instead of failing the payload.
2. Fall back to xattr storage that doesn't require a sidecar filename.
3. At minimum, name the actual failing path (`._aaa…`) in the error.
